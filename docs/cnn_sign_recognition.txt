Chapter 1. Introduction 

1.1. Project context 

The development of human society is at a critical point. Deep Learning, Machine 
Learning, and AI models are increasingly present in our lives. The most powerful countries in 
the world, the USA and China, are investing billions of dollars in the development of new 
models, the goal being clear: power and political influence, which can be secured today in 
only one way, that being technological supremacy. 

Opinions are divided. Some declare that Artificial Intelligence (AI) will fundamental-
ly and irrevocably change the world we live in, while others consider that it will remain a 
simple tool that will make human life easier. Regardless of what the future holds, one thing is 
certain: whoever doesn't adapt to the new technologies will be left behind. Therefore, under-
standing that cutting-edge technology is necessary for anyone who wants to remain relevant 
in tomorrow's job market. 

1.1.1. Application domain 

This paper seeks to investigate the feasibility of implementing AI in systems with 
processing/energy constraints, such as microcontrollers. The scale at which this project was 
realized is obviously small, but it incorporates the principles and technologies that support the 
AI explosion, while also having well-defined practical uses. Computer vision is used today in 
security, surveillance, mobile phones, healthcare, etc. And the number of applications will 
only grow in the years to come. 

The growth of AI application brings with it exponential energy consumption as well. 
The DeepSeek incident panicked the whole USA AI market [11]. This proves that the whole 
world recognizes the importance of reduce power consumption, highlighting the importance 
of limited resources machine learning systems. 

In the last few years, we have seen a lot of applications computing being moved to 
cloud and even thought cloud computing is great, its latency must be considered even for the 
most basic applications. Extending the idea to complex computational applications, like 
machine learning, cloud communication latency would become a nightmare. To solve this 
issue, we need to take the smart edge approach, which is seen to be rising the last few years. 

Smart Edge is a distributed computing paradigm that processes data near its source 
and that incorporates machine learning decision making [12]. It is a concept often mentioned 
in the context of Internet of Things devices, because of its advantages such as low latency, 
real-time capabilities, reducing the need of complicated data security mechanisms and 
decreasing the frequency of cloud communication. 

One of the applications of the Smart Edge concept are the Intelligent WSNs (Wireless 
Sensor Networks). Intelligent WSN’s are networks of intelligent sensors, that can be used to 
monitor and/or control activities on large areas. Some applications are Agriculture, Industrial 
Automation, Smart Cities and so on. 

Given the large areas where those sensors are distributed, the challenge of supplying 
them with the required power might prove a hard one. Therefore, thinking in terms of power 
efficiency becomes again a priority. Which is leading to the notion of resource constrained 
platform. Visualization of the thesis niche might have become difficult at this point, so a 
graphical view can be seen in Figure1.1.

The idea of this dissertation is to use the machine learning pattern recognition and 
decision-making capabilities on a low power, low memory, real-time microcontroller which 
could be than used in a larger network through Smart Edge.

MAX78000 is the development board used for this project. MAX78000 is a

Figure1. 1 MAX78000 block diagram [1] 

1.1.2.1.2. Arm Cortex M4 

Arm Cortex M4 is a 32bit RISC (Reduced Instruction Set Computing) processor 
designed for embedded and real-time applications. The RISC architecture is using only a 
small set of instructions, which is making it very reliable and predictable execution times. 
Using the Cortex M4 processor as the main processing unit is great because of its features: 


- Low power consumption 
- Sleep mode 
- Harvard architecture (separate instruction and data buses for fast access) 



- DSP (Digital signal processing) capabilities 
- Tightly Coupled Memory (TCM) for high-speed memory accesses 
- Nested Vectored Interrupt Controller (NVIC) for fast and priority configurable 
interrupts 


1.1.2.1.3. RISC-V Coprocessor 

RISC-V processor is a 32bit processor as well. Contrary to the Arm Cortex M4 it has 
been designed by Analog Devices to enhance the ML capabilities of the CNN accelerator, 
however it can run application and control code as well. It has been designed for low power 
consumption as well. 

This was possible because RISC-V is an open-source architecture that anyone can 
use, contrary to Arm that is well established company who is charging a fee in return of 
letting anyone use their architecture. 

1.1.2.1.4. Convolutional Neural Network (CNN) Accelerator 

The CNN Accelerator is a specifically designed for computing mathematical 
operations named convolutions. Even though the convolution has a more general meaning 
added to it, in the case of the MAX78000 the convolution operation is defined on matrices. 

Given an input matrix A of size m x n and a kernel of size k x k, the convolution 
operation is executed by sliding the kernel over the whole input matrix and making the dot 
product between the 2 matrices at each step.

The MAX78000 CNN accelerator has 64 cores. Also, it is an 8bit architecture, 
meaning that all input, weights, and biases have 8 bits. This has been chosen specifically to 
achieve low power consumption. 

Besides convolutions, the CNN core needs to be able to perform other operation as 
well. After fetching the inference data from memory, the core needs to be able to do max 
polling and average polling in case it is requested by the configuration. The working principle 
of the CNN core can be seen in Figure1.3. 

 

Figure1. 2 CNN core architecture [2] 



 

Processors are gathered in 4 by 4 groups, Figure1.4. The RAM inside CNN is 32 bits. Every 
RAM address can feed 4 processors at ones, because each processor has an 8bit architecture. 
At any time, any processor can get the results from any other processor inside the CNN. 

 

 

Figure1. 3 Processor group [2] 

Together 4 groups from a processor quadrant, Figure1.5. Each quadrant has access to 
512bytes of bias RAM. At this point it can be explained how the convolution computation an 
ML algorithm is done: 

• Convolve the channel with the kernel. 
• Convolve all the other channels from this layer with the kernel. 
• Apply RELU/ABS activation function. 
• Sum all the values from all groups together 
• In case of more than 16 channels per layer, the Processor quadrant SUM can be 
added to the SUM of the rest of the Quadrants. So up to 64 channels can be 
computed and added at ones. 
• However, in case there are more than 64 channels, the current SUM can be cached 
in the Multipass Accumulator. This way the processor Quadrant can add together up 
to 1024 virtual channels. 
• The internal CNN logic is designed to support up to 32 layers. 



 

Figure1. 4 Processor Quadrant [2] 

The user shall only provide a state machine and the layer configuration, as the CNN internal 
logic will execute the computation of all the ML algorithm layers.

1.1.2.2.4. Gradient Descent 

Gradient descent is an optimization algorithm used to converge a function to its local 
minimum. It is used in Machine Learning to adjust the weights and biases of the model in 
such a way that the final loss function in reduced to a minimum. It updates the parameters in 
the opposite direction of the partial derivative (or gradient) of the function with respect of the 
parameters. Below is the formula of the gradient descent, where x is the parameter to be 
optimized, 𝛼𝛼 is the learning rate and 𝛻𝛻𝛻𝛻(𝑥𝑥𝑛𝑛) is the gradient of the loss function with respect 
the parameter.

The optimizer used on this paper is ADAM. ADAM is using Mini-batch Gradient 
descent, a type of Gradient descent that uses a small subset of the data to update the 
parameters. 

1.1.2.2.5. Backpropagation 

 

Backpropagation is an algorithm used to compute the gradient of the loss function 
with respect to each weight in the network. The algorithm has four stages: 

1. calculating how wrong the prediction was 
2. Propagating that error backward from the output layer to the input layer 
3. Computing the gradient of the loss function with respect to each parameter, 
using the chain rule from calculus 
4. Updating weights using gradient descent

3.1. Face identification [7] 

The Face identification algorithm [7] used is called AI85FaceIdNet. This algorithm is 
a lightweight version of FaceID algorithm, and it has a reduced number of parameters (from 
7.5 million to less than 450k) to make it fit on MAX78000, both from the size and runtime 
point of view. 

AI85FaceIdNet is a 9-layer neuronal network, that is using 3x3, 1x1 convolutions, 
ReLu activation functions, max and average pooling. It was trained over 100 epochs, by 
using the Adam optimizer. 

 

Figure 2. 1 AI85FaceIdNet architecture [7] 

3.2. Key word spotting [3] 

The Key Word spotting algorithm [3] was developed by Google, and it can identify 
up to 20 key words. The purpose of such an algorithm is to listen continuously to detect a key 
at any given time. Because it needs to run continuously it make sense to have it run on a low 
power device such as MAX78000. The recognized command can then be used to trigger a 
more complex Neural Network or functionality. The principle behind this algorithm using 
Arm Cortex M4 core to convert Speech into Mel Frequency Cepstrum Coefficients (MFCC). 



The MFCC output can be seen as a 3channel picture, which can be fed to the CNN that will 
return a probability that the spoken word is one of the 20 recognizable words. 

From the CNN point of view, processing this algorithm is no different from others, 
the different part from other algorithms is the digital signal processing part, that is done by 
the Arm Cortex M4. For the conversion the following steps need to be taken: 

1. The amplitude domain is being windowed. That means that we analyze only the 
frequences in a 25ms window. After that we shift the analysis with 10ms. 

2. The Fast Fourier Transform will decompose the signal from the microphone into 
the relevant sinusoidal functions. Basically, transforming the time domain into frequency 
domain. 

3. Our perception of sound frequencies is logarithmical. That means that we can 
differentiate the lower frequences a lot better than higher frequences. To take our perception 
of sound in consideration, we must convert the frequences from Hz to Mel. To do that we 
have to apply Mel Filter banks to the frequency domain. 

4. Logarithm is applied to compress the dynamic range. 

5. Discrete Cosine Transform (DCT) is concentrating the information into the first 
few coefficients. By doing this the computational necessity is reduced. 

 
In Figure2. 1 the steps taken for the conversion can be also visualized. 

 

Figure 2. 2 Converting Speech into MFCC [3] 

3.3. Motor fault detection [8] 

In reference [11], Analog devices is showing that the MAX78000 device has 
applications in industrial fields as well. In this application MAX78000 is used to monitor an 
electric motor and to detect different faults that the motor might have. The setup is using a 3-
axis accelerometer that is converted into the frequency domain using FFT. The CNN is being 
fed a 256 x 3 tensor. Here the 3 represents each axis and the 256 is representing different 
frequences outputted by the FFT. The model will output a 1-dimensional tensor where all 
present frequences were identified. 

3.4. L3U-net: Low-Latency Lightweight U-net Based Image Segmentation 
Model for Parallel CNN Processors [9] 

U-net is a common model used in medical imaging (e.g., tumor detection). The U-net 
model is an encoder-decoder structure that is reducing the spatial resolution by increasing the 
channels. After the encoding, the decoding will unsample the data to the original resolution. 



However, this model is too complex to run on MAX78000, this is why the researchers 
modified it to a lightweight version named L3U-net. 

 

Figure 2. 3 U-Net architecture 

To reduce the complexity further down, they used a data folding technique Figure2.3. 
The input layer has a high resolution, but only a small number of layers. Because of that 
almost all the CNN cores are pending. By data folding they are down sampling the image, so 
increasing the number of channels and reducing the resolution (this way no data is being 
lost). By doing this the latency is reduced, because this technique is enabling the use of more 
CNN cores on the first layers, optimizing parallelization. 

The goal of the model is semantic segmentation, which means adding a label to each 
pixel (e.g., if the pixel is used in a tree, the set label will be tree). In the paper it is stated that 
an accuracy of 91% to 99% was achieved. 

 

Figure 2. 4 Visualization of the data folding technique [9]

Because MAX78000 is a low power edge device, its weight memory is very limited. 
To go around this limitation, a small model has been chosen: ai85cdnet. 

There are many variations of this model; however, the one chosen for this study is a 
really small one, having only 7 layers. As seen in Figure 4.5, the model has 6 convolutional

FusedConv2dReLu

Linear 

This method has to purposes. One is to flatten the previous

is as a fully connected layer. This will connect every neuron

It defines the padding of the layer. All layer’s padding is set to 1,

Activation function that will be used for each layer. All layers are using

4.3. Functionality implementation 

4.3.1. Initialization 

 

Around the generated weights and biases, the functionality must be designed. The first 
requirement is to be able to initialize the CNN. This has several steps: 





- Select a peripheral clock. A 50 MHz clock has been selected, which has been 
divided from the 100MHz system clock 
- Enable CNN boost. Enables faster inference times, which as a result reduces the 
overall power consumption 
- Call cnn_init() function, which will initialize CNN SRAM 
- Call cnn_load_weights() function, which will fetch the weights and biases from 
flash and store them into CNN SRAM 
- Call cnn_configure() function, which will initialize every layer 


Even if the initialization is done successfully, at this point inference is impossible. 
This is because no data is present inside CNN SRAM. So the next initialization step is to 
initialize the camera and the DMA necessary to transport the data into SRAM. 

 That being said, the next step is to initialize the Direct Memory Access (DMA), using 
MXC_DMA_Init() function. In the background, this function is enabling the DMA 
peripheral clock and resetting all DMA channels. Next dma_channel = 
MXC_DMA_AcquireChannel() will return the next free DMA channel that can be use. 

Here is a good point to explain one of the biggest challenges of developing this study. 
The challenge was a DMA channel overflow. In order to solve this, the bound rate of the 
camera had to be adjusted to be in sync this the DMA channel bound rate, by using 
camera_write_reg(0x11, 0x1) function. 

Ones the DMA channel is functional and running, the next step is to initialize the 
camera. This is of course done by calling camera_init() function, followed by 
camera_setup() function. The second one is responsible for camera configuration: 

- resolution 128x128 pixels 
- pixel format, here RGB888 has been chosen, because of CNN and model constrains 
o RGB because the model is expecting a tensor of 3x128x128 for inference 
o 888 because the CNN can work only with 8 bits data 



- streaming DMA mode is used to allocate memory with a buffer too keep at least 
two horizontal lines of a camera image for CNN streaming 
- DMA channel selection, calculated previously 


 

Next the prescaller for the camera has been chosen as 0x1 to prevent overflows. 

The last initialization step is TFT (thin film transistor) display initialization. This was 
done by using an already existing logic and templates from the TFT library. 

4.3.2. Running 

After the initialization is complete, the software start running in an infinite loop. First 
thing inside the loop the camera is instructed to capture an image, by function call 
camera_start_capture_image(). Following this the CNN is started, and the input is being 
loader in CNN SRAM. 

At this point, to reduce power consumption, the Arm processor enters sleep mode, 
until CNN is done processing. Given the fact that CNN processing in this case takes around 
12ms, a lot of actual power is saved. 

After unloading the data, CNN is put to sleep, again to reduce power consumption. 
Processing the output data is done, by passing it through a SoftMax. The purpose of the 
softmax is to convert a vector of values into probabilities that sum to 1. As seen in 
Figure4.16, marked in red, the classification results are intelligible values. By applying 
SoftMax to those values, one will get a set of probabilities that sum to 1. 

 


 

Figure 4. 17 SoftMax output 

 

Ultimately, the inference results are being shown on the screen using the TFT library. 
From this point it starts over again. The whole process takes approximately 56ms. 

 

 

 

 

 

 

 

 

 

 

 

 





Chapter 5. Theoretical and experimental results 

5.1.1. Evaluation on the neural network performance 

Validation has been done in two steps. 

1.The first one was done in on the training laptop, in a SIL (Software in the loop) 
manner. Using the train.py script, images have been fed to the neural network and as a result 
a confusion matrix has been generated. This approach was used in order to simplify the 
optimization process, by having a way to evaluate the results of training, without the 
necessity of flashing every time. 

2. The second validation step was in a HIL (hardware in the loop) environment. This 
means that validation has been done directly on target hardware, so on the MAX78000 
evaluation board. This test environment differs from the previous one by involving the 
complexity of real world. 

Simply by comparing the results of the two test environments, it has been observed 
that the neural network tends to make mistakes more often on the HIL environment, SIL 
environment being almost perfect (see confusion matrix). On the hardware-in-the-loop (HIL) 
system, the neural network sometimes misclassifies inputs from the 'unknown' class as 
'no_entry'. 

Tests were done in different times of the day, with different light. The conclusion is 
that under different light conditions, the neuronal network tends to interpret wrong results 
more often. 

To address this issue, the training dataset was augmented with more examples from 
the 'unknown' class to increase its representation and improve the network's ability to 
distinguish it from the 'no_entry' class. However, due to the lack of diversification, the NN 
still makes mistakes.

5.1.3. Evaluation from the perspective of inference time 

The inference time is small (12ms), even on a bigger model, the inference time is still 
a lot smaller than using a server to process the information, because of the induced latency of 
sending the data and request-response sequence latency. 

This makes the usage of edge devices great also for time critical applications. By 
implementing a RTOS on such an edge device, one could also implement complex state 
machines and servicing multiple tasks without having to worry about inference time, because 
it is done in the background, without CPU intervention. 

5.1.4. Evaluation from complexity point of view 

An edge device simply has to little hardware resources to handle complex tasks. For 
example, it would never be used in tasks like self-driving cars. The data processing and 
memory needs are simply too great for such a battery driven device to handle. 

However, they are great for smaller tasks, where, for example, human access is 
difficult, or the monitoring area is too great. 

As a consequence to both memory restrictions and computational restrictions, it 
becomes impossible for the model to learn in improve by interacting with the surrounding 
environment, also known as Reinforcement Learning. 

5.1.5. Evaluation on memory and storage restrictions 

Both SRAM and flash memory make it impossible to run large models. Running a 
neural network on an edge device requires heavy quantization. This could be seen during 
evaluation phase, where the confusion matrix was perfect in the case of a quantized model,

6.1.1. Summary and contributions 

 

The purpose of this master thesis was a study the feasibility of using edge devices 
with neuronal network capabilities. To achieve that I have contributed by: 

- choosing the right model for the classification task 
- training, testing and optimizing the chosen model 
- providing the low-level C code logic necessary to load the data into the 
Convolutional Neuronal Network accelerator 
- analyze the result

6.1.2. Advantages and limitations 

 

At the end of the study, it can be concluded that Neural networks on edge devices 
have a set of well-defined advantages like: 

- low power consumption and therefore low cost 
- fast response time 
- reduces bandwidth usage, no need to continuously stream data to the cloud, as 
processing is done locally 
- data security 
o Today there are a lot of data security protocols. However, there is no safer 
way to keep the data secure, than to keep the device disconnected from the 
internet, or to connect it only an isolated local area network. 



- offline operation 
o it does not need internet connection, so it can operate even in the most 
remote places 



- scalability 
o because processing is done locally, there is a reduced load on the network 
infrastructure 





On the other hand, the usage of edge devices comes also with disadvantages, like: 

- limited computational resources 
o as an effect edge devices can handle only low complexity tasks 
o reinforcement learning is not possible 



- restricted memory usage 
o requires heavy quantization, which does hurt the model accuracy and 
performance 



- energy constrains 
o Even if an edge device can run on a battery for an extended period of time, 
the lifetime of the battery is still limited. This can be considered a 






disadvantage because it may require human intervention in order to change 
the battery 





6.1.3. Further improvements and development 

 

Improvements can be done in two directions. 

The first one is the model. The model is far from perfect, and the following 
improvements can be done to it: 

- increase the data fed to the model during training 
o One of the advantages of neural networks is scalability. This has been 
proved multiple times in the field. So as a general rule: the more data the 
better the overall result 



- improvement on the model 
o As a general rule when working with neural networks, parallelizing more 
computations leads to faster inference times. However at the moment the 
first layer is using only 3 cores (see GTSRB-hwc.yaml in appendix). This is a 
major bottle neck. In the research done at [9], they applied data folding 
techniques to the image, prior to feeding it to the network. Applying the 
same technique will improve inferring time. 



- GTSRB data set has 43 types of signs 
o a model to classify all of them can be implemented 



- power consumption can be improved, by using ultra-low power mode 
- usage of RISC V core to control the CNN, as it is designed for this purpose 
o The RISC V core is tightly coupled with the CNN hardware, because it has 
direct, low-latency access to the CNN accelerator’s control registers. This 
will also free the ARM Cortex M4 core to run other tasks.
